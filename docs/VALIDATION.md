覆盖范围：

- 16 兵种、74 枚基础单位币、双/四人地图、选兵顺序及历史阵容。
- 狂战士连动支付后的骑士资格、元帅/军旗手触发的额外能力、长枪兵同步战损、卫队防守选择和恢复、牧师强制抽币、步兵两单位协同。
- 双人 80 个随机阵容最多各 500 步、四人 40 个随机阵容最多各 800 步，逐步检查币守恒和合法候选唯一性；自然结束时提前停止。
- 正常与紧凑观测的可见性、对手暗币重新分布不改变观察、暗弃动作的公共日志脱敏。
- 快照随机状态、悬挂防御选择、移除币计数、克隆隔离、逐步回放与摘要、终局团队奖励、截断区别。
- 非法/过期行动、未授权席位、CSRF、签名伪造、并发重复提交、数据库失败保持内存局面不变。
- 双人随机开局经真实 ASGI HTTP API 318 次决策自然胜利；四人 403 次自然胜利；双方/四方最终视图一致，并验证从持久化日志完整重放。
- 清除内存房间和会话缓存后，存档、席位权限及未过期动作签名恢复。
- JSON Lines 工具的 reset/observe/step/赛后导出，进行中拒绝完整私有回放。

## 真实浏览器验证

使用本机实际运行的 FastAPI + Vite，不是静态 fixture：

1. 开局页面创建双人对局、加入席位、选择部署、确认执行。局面从 revision 0 到 1，棋盘和手牌同步变化。
2. 停止并重启后端，重新载入原标签，局面 revision 1 与会话恢复。
3. 创建四人选兵局，按实际决策者逐席切换，完成全部 12 次选择后各席抽到三币，进入正式行动阶段。
4. 依次完成四名玩家的首次部署，局面从 revision 12 到 16，轮到原先手继续行动，四支单位均可见。
5. 兵种面板能力说明可见，选择行动与确认按钮可操作。
6. 在 390 × 844 视口检查手机断点，侧栏收起、棋盘和操作控件可访问，无横向内容溢出；已恢复普通视口。
7. 保存实际四人局截图：`output/screenshots/base-four-player.png`。

浏览器中为测试而用席位邀请链接切换同一会话，**没有把这项检查冒充四个并发浏览器身份测试**。隔离身份与并发使用独立 TestClient 会话验证。

## 性能

另有独立 200,000 步 × 3 组基准，原始 JSON 与测量边界见 [performance.md](performance.md)。纯双人状态推进约 5.7 万决策/秒，每步包含紧凑观测约 3.3 万决策/秒，均不包含模型推理。

## 范围与剩余限制

- 不含 DLC 和模型代码；后续训练想法已写入 training-plan.md。
- 没有独立第三方规则引擎做全状态差分验收，不宣称穷尽所有状态。
- 跨队友的后续决策归属、两步折返、无法行动的剩余步兵等边缘解释在 rules.md 中明确记录。
- 没有把预算截断冒充官方和棋；极端循环局可持续到调用方停止。
- 本地服务不是公网账户/匹配平台，SQLite 缓存方案限定一个服务工作进程。
- 未做多核扩展或原生内核吞吐验收，不宣称已达到硬件极限。
